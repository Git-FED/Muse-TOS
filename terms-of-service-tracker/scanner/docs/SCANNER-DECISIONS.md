# Scanner Decisions

## D1 — Check before the action

The scanner is a pre-flight check, never a post-action report. Once an action happened, it cannot honestly be labeled a pre-check.

## D2 — Written rules are the only authority

A verbal okay never overrides the written rules. The scanner quotes the written rule and treats human instructions as a separate source that may contradict it.

## D3 — Exactly four verdicts

The vocabulary is deliberately closed: CLEAR, CONFLICT, CONTRADICTION, and UNCHECKED. There is no fifth “probably okay” state.

## D4 — Exact citations are mandatory

Every non-UNCHECKED verdict cites the exact rule text, its source, and its snapshot date. Without that evidence, the result is an opinion rather than a scan.

## D5 — UNCHECKED is a result

A missing, blocked, moved, unreadable, or unsnapshotted rules page produces UNCHECKED with a reason. It never silently passes.

## D6 — Every verdict is labeled

Each verdict is VERIFIED or UNVERIFIED. VERIFIED requires a hand check with live evidence and a stated time; worker-reported or unchecked results are UNVERIFIED.

## D7 — Advice only

The scanner never posts, emails, or contacts a platform. No action is taken without a separate order.

## D8 — Module inside the tracker

The scanner lives inside the tracker repo and reads its snapshots. It is not a separate repo and it is not a second source of truth.

## D9 — The contradiction case is a reference pattern

The Nov 7 r/MuseAgent case is the contradiction reference example. The important pattern is human instruction versus written rule, not a grudge against a person.
